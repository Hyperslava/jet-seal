# Тесты «Реактивного тюленя»

Тесты написаны по `TEST_CASES.md` и `SPEC.md` (37 тест-кейсов: 33 модульных, 4 сценарных). Используется стандартный `unittest`, устанавливать ничего не нужно.

## Как запустить

Из **корня репозитория**:

```bash
python -m unittest discover -v
```

Эквивалентная команда, где явно указаны папка с тестами (`-s tests`) и корень проекта (`-t .`):

```bash
python -m unittest discover -s tests -t . -v
```

В обоих случаях запускать нужно из корня репозитория, иначе не найдутся модули `jet_seal` и `tests`.

Один файл или один тест:

```bash
python -m unittest tests.test_scenarios -v
python -m unittest tests.test_jet_seal.TestDive.test_TC_18_too_deep_and_max_depth_boundary -v
```

## Что в папке

| Файл | Содержание |
|---|---|
| `test_jet_seal.py` | Модульные тесты TC-01…TC-32 и TC-37 по схеме AAA (Arrange / Act / Assert): конструктор, `move`, `dive`, `surface`, `can_overcome`, `calculate_energy`, `refuel`, `damage_fins` / `repair_fins`, `get_status`, иерархия исключений и атрибуты только для чтения (TC-37). Проверки с несколькими входами сделаны через `subTest`. |
| `test_scenarios.py` | Сценарные тесты TC-33…TC-36 по схеме Given / When / Then: «Шторм у Рифа Трёх Братьев», «Побег из пересохшей лагуны», «Контрабанда через дамбу», «Выход на берег с глубины». Каждый тест проходит сценарий из раздела 4.2 ТЗ шаг за шагом. |
| `pilot.py` | Класс `Pilot` — капитан тюленя. Скрывает вызовы `JetSeal` за действиями на доменном языке (`плыть`, `ползти`, `нырнуть`, `всплыть`, `преодолеть`, `заправиться` и т. д.). Используется в сценарных тестах. |
| `helpers.py` | Вспомогательные функции для модульных тестов: `make_swimming_seal()` (тюлень, уже находящийся в воде, с заданной энергией) и `snapshot()` (снимок состояния для проверок «состояние не меняется»). |
| `__init__.py` | Пустой файл. Делает `tests` пакетом, чтобы работали импорты и поиск тестов. |

В имени и докстринге каждого теста указан ID из `TEST_CASES.md` (например, `test_TC_14_dive_success`), так что тест легко найти по таблице трассируемости.

## Почему тесты сейчас не запускаются

Тесты импортируют модуль `jet_seal` (класс `JetSeal` и исключения из раздела 6 ТЗ), которого ещё нет. Это ожидаемо: проект ведётся по TDD, сначала пишутся ТЗ и тесты, а реализацию потом пишет разработчик (роль D).

Сейчас запуск заканчивается так:

```
ModuleNotFoundError: No module named 'jet_seal'
FAILED (errors=2)
```

Две ошибки — по одной на файл с тестами. Это не ошибки в тестах.

Тесты заработают, когда в корне репозитория появится `jet_seal.py` с классами `JetSeal`, `CrazyVehicleError`, `JetSealError`, `JetSealCannotFly`, `JetSealNoStrength`, `JetSealNoFins`, `JetSealTooDeep`, `JetSealCannotDive`, реализованными по `SPEC.md`.
